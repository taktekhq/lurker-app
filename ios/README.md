# Lurker iOS

Share photos from your iPhone, get Reddit post drafts back. You post them
yourself. SwiftUI, iOS 18.0+, iPhone only, portrait. Bundle id
`io.taktek.lurker`, share extension `io.taktek.lurker.share`, shared keychain
group `<team prefix>io.taktek.lurker.shared`. See the repo's [SPEC.md](../SPEC.md) for the full
API contract this app talks to.

Nothing in this app is specific to one person or one server: there is no
built-in URL or token. You set your own worker's address and your own token
in the app's Settings screen, once, and both the app and the share
extension read them from there.

## Layout

```

  Team.xcconfig.example     committed template -- copy to Team.xcconfig
  Lurker/

    Views/

      ShareRowView.swift      one share's card: photos, note, status, its drafts, action buttons
      DraftCardView.swift     one draft: sub, title, body, why, rule notes, copy buttons
      RemotePhotoView.swift   loads a share's photo through PhotoLoader (needs the bearer token)
      SettingsView.swift      server URL, token, Test button
    Lurker.entitlements       Keychain Sharing
  LurkerShare/                the share extension target
    ShareViewController.swift  NSExtensionPrincipalClass: hosts ShareComposerView via UIHostingController
    ShareComposer.swift        loads shared images, resizes them, sends, tracks state
    Views/
      ShareComposerView.swift  thumbnails, note field, Send, progress, sent/error states
    LurkerShare.entitlements   same Keychain Sharing group as the app
  LurkerTests/                placeholder app-level test target
  LurkerKit/                  local Swift package -- all testable logic lives here
    Sources/LurkerKit/
      Models.swift             Share, Draft, ShareStatus -- the JSON shapes from SPEC.md
      Client.swift              the API client (shares, createShare, updateStatus, deleteShare, photo)
      Transport.swift           URLSessionTransport, and the protocol tests fake
      APIError.swift            decodes a non-2xx response
      Multipart.swift           builds the multipart/form-data body for POST /v1/shares
      ImagePrep.swift           resize to 1600 px long edge, JPEG quality 0.8
      SettingsStore.swift       protocol: serverURL(), token(), set(serverURL:token:)
      KeychainSettingsStore.swift  SettingsStore backed by the shared keychain

    Tests/LurkerKitTests/      swift test --package-path LurkerKit
```

## Tooling

- **XcodeGen**, expected at `~/.local/bin/xcodegen` (installed from the
  GitHub release zip, no Homebrew):
  ```
  curl -L -o /tmp/xcodegen.zip \
    https://github.com/yonaskolb/XcodeGen/releases/download/2.46.0/xcodegen.zip
  unzip -q /tmp/xcodegen.zip -d ~/.local/opt/xcodegen-2.46.0
  ln -sf ~/.local/opt/xcodegen-2.46.0/bin/xcodegen ~/.local/bin/xcodegen
  ```
  `~/.local/bin` must be on `PATH`. Re-run `xcodegen generate` any time
  `project.yml` changes; `Lurker.xcodeproj` is generated and git-ignored.

- **Xcode 16 or newer** (iOS 18 SDK, Swift 6).

## Signing

`Team.xcconfig` (git-ignored) holds `DEVELOPMENT_TEAM`, empty by default.
Copy `Team.xcconfig.example` to get started:

```
cp Team.xcconfig.example Team.xcconfig
```

With it empty, the project still builds for a generic iOS device as long as
`CODE_SIGNING_ALLOWED=NO` is passed (signing is skipped entirely):

```
xcodegen generate
xcodebuild -project Lurker.xcodeproj -scheme Lurker \
  -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
```

To run on your own iPhone or in a simulator, fill in your Team ID in
`Team.xcconfig` and open `Lurker.xcodeproj` in Xcode. The first build will
ask you to enable Keychain Sharing for your own team; Xcode's
"Automatically manage signing" does this for you. There is no App Group, so
nothing has to be registered by hand.

## Pointing the app at your own worker

Open the app, tap the gear icon, and enter:

- **Server**: your deployed worker's URL, e.g. `https://lurker.yourname.workers.dev`.
- **Token**: the app token your worker was configured with (`APP_TOKEN` in
  `worker/README.md`).

For your own copy, skip this screen entirely: put `LURKER_SERVER` and
`LURKER_TOKEN` in a git-ignored `Defaults.xcconfig` next to `Team.xcconfig`
(see `Team.xcconfig.example`) before `scripts/archive.sh`. The build carries
them, and Settings only overrides them. Anyone holding that build can read
the token out of it, so only do this for builds you keep to yourself.

Or open a setup link on the phone and both are saved in one tap:
`lurker://setup?server=<url-encoded https URL>&token=<app token>`.

Tap **Test** to confirm the app can reach your worker (it calls
`GET /v1/shares`) before saving. Both values are saved to the Keychain, in
a keychain group both targets share (`<team prefix>io.taktek.lurker.shared`;
the prefix is read at run time from the `AppIdentifierPrefix` Info.plist key),
so the share extension can read them without the app needing to be running.

If you fork this app under your own bundle id, change `PRODUCT_BUNDLE_IDENTIFIER`
and the keychain group suffix (`io.taktek.lurker.shared`, in both
`.entitlements` files and in `KeychainSettingsStore.defaultAccessGroup`).

## Sharing photos

From Photos (or any app with image attachments), use the share sheet and
pick **Lurker**. It accepts 1 to 10 images at once. The extension resizes
each photo to 1600 px on its long edge and re-encodes it as JPEG at quality
0.8, which drops the original's EXIF data, GPS included. Add an optional
note, tap **Send**. If no server is set yet, it tells you to open Lurker and
add one first, instead of failing silently.

## Running the checks

```
cd ios
scripts/build.sh                      # xcodegen generate, swift test, generic-iOS build
swift test --package-path LurkerKit   # just LurkerKit, while iterating
```

`scripts/build.sh` never touches the simulator (the Mac this was built on
has 8 GB of memory, so every `xcodebuild` run matters); it generates the
project, runs LurkerKit's unit tests as a plain Swift package, then does a
generic-device build with `CODE_SIGNING_ALLOWED=NO`. A full `xcodebuild test`
run on a simulator is a separate, occasional check, not part of this script:

```
xcrun simctl list devices available   # pick a name
xcodebuild -project Lurker.xcodeproj -scheme Lurker \
  -destination 'platform=iOS Simulator,name=<some available simulator>' test
xcrun simctl shutdown all
```

## Archiving and uploading to TestFlight

`scripts/archive.sh` archives the app (Release config) and uploads it to App
Store Connect with `xcodebuild -exportArchive -destination upload`, signed
with an App Store Connect API key (no Apple ID needed in Xcode, no GitHub
Actions, no simulator). The App Store Connect app record must already exist
(Apple's API can't create one) and both bundle ids must be registered (the
API can: `POST /v1/bundleIds`).

```
ASC_KEY_ID=... ASC_ISSUER_ID=... ASC_TEAM_ID=... \
  ASC_KEY_PATH=/path/to/AuthKey_<id>.p8 \
  scripts/archive.sh              # archives and uploads
scripts/archive.sh --export-only  # stops after making the .ipa, no upload
```

The key needs the App Manager (or Admin) role. The build number is the
current UTC time, so every upload is new. `ExportOptions.plist` is generated
inline by the script into a temp directory; it is not a committed file.
